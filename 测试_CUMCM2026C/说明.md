## 模型与结果

**模型**：把四个问题的确定性内核统一写成一个线性规划——决策变量为购电
$b_t$、充电 $c_t$、放电 $d_t$、弃光 $u_t$ 与储电量 $s_t$，约束为功率平衡
$V_t+b_t+d_t=L_t+c_t+u_t$、电量递推 $s_t=s_{t-1}+\eta c_t\Delta t-d_t\Delta t/\eta$、
上下限 $0\le c_t,d_t\le 5000$、$1200\le s_t\le 10800$，目标为购电费最小。
问题 1 额外要求日末储电量回到初值。全部用 HiGHS 求解，无启发式。

| 问题 | 结果 |
|------|------|
| 1 | 全天购电量 **59482.6990 kWh**、购电费 **35126.9486 元**；比无储能基线 48052.0466 元**省 26.90%** |
| 2 | 334 天购电量 **20189815.8 kWh**、购电费 **12254765.72 元**，紧急购电恒为 0 |
| 3 | 计划+调整结算 13218904.90 元、紧急购电 405164.6 kWh（174.24 万元），合计 **14961318.24 元** |
| 4 | 实时电价下：完美信息 12841054.36 元；预报+调整 15626108.38 元 |

## 建模过程中发现并处理的三件事

**① 问题 2 的紧急购电恒为 0，是先于计算就能证明的。** 题目说「在每天 0:00
制定当天计划」，而附件 2 给的是当天负荷与光伏的**实际值**，故计划时信息完美；
又因购电功率无上限，任意一天都存在「缺多少买多少」的可行解。既然计划时已知
实际数据，最优计划必然精确满足负荷——334 天的数值结果是 0 kWh，与证明一致。
这一点也说明问题 3 才是题目真正要考的地方。

**② 附件 3 的光伏预报误差是系统性偏差，不是零均值噪声。** 按
$(发布时刻, 步长)$ 分组统计「实际 − 预报」：0:00 发布、步长 9 小时处为
**−666 kW**，步长 18 小时处为 **+400 kW**，量级与标准差（426 / 315）相当。
若按常规当作零均值噪声处理，规划用的光伏序列会系统性偏移，缺额被 5 倍电价
惩罚。据此做了两步：先用 1 月数据标定偏差 $\beta(发布时刻,k)$ 并逐段扣除，
再按边际平衡 $1.5(1-q)=3.5q\Rightarrow q=0.30$ 取 70% 分位、即按
$z\cdot\sigma$（$z\approx0.524$）留余量。两步合计把总费用从 1600.7 万元
降到 **1496.1 万元**（−6.5%），其中偏差订正贡献 1503.0 万元（−6.1%），
逐时段分位对冲再贡献 −0.5%。

**③ 余量必须按区间取，不能全天统一。** 夜里光伏恒为 0、$\sigma=0$，
在这些时段留余量等于用 1.5 倍电价空买电。实测全天统一加余量反而比不加更贵
（1519.5 万元，比不订正只对冲还差）。最终按 $z\cdot\sigma(\text{发布时刻}, k(t))$
逐时段取，夜间自然为 0。

## 模型验证（五层）

| 检验 | 结果 |
|------|------|
| LP 双算法交叉（highs-ds / highs-ipm） | 目标值完全相同 |
| 全部约束回代核验 | 最大违反量 1.8×10⁻¹²（功率平衡）、4.5×10⁻¹³（电量递推） |
| 松弛检验（单调性） | 放开日末电量约束 35126.95→32909.87；放宽区间到 [0,12000]→33556.75，均下降，符合「放松约束不劣化」 |
| 独立反算（只读结果文件） | 问题 1 能量守恒相对差 1.1×10⁻⁹；逐日抽查 6 天，表内全天购电费与重算值差 <1×10⁻³ 元 |
| **与附件 5 模板逐列比对** | 5 个文件的工作表名、列数、表头逐列比对通过；差异只有时间标签一处（见附录 B.1），且该差异必须能按「模板整体右移一格」逐项对上才算通过，不是「都不同就算了」 |

第四层是刻意「不复用求解过程内存对象」的：它只读已写出的 `result*.xlsx`
与原始附件反算，能查出「算对了但没写对」。这一步实际查出了三类错误——
模板列数与预期不符（少了「全天购电量」「全天购电费」两列）、写作过程中
`dict.get` 的默认值被无条件求值导致的 `KeyError`，以及日期列写成了字符串
而模板用的是 Excel 日期值。

第五层是补做交付自检时加的：加完之后才发现结果文件里还有两处不达标——
时间列的末格标签写成了模板里那个并不存在的 `0:00+1-0:10+1`，以及紧急购电表
混进了大量 0.0006 kWh 的求解器残差。两者都已修正，论文附录 B 有说明。

## 两处按自己判断做的取舍

**① 时间区间的标签与模板不同。** 附件 1 给的是 144 个时刻（`0:10` … `0:00+1`），
每个时刻代表「以它结尾的 10 分钟」。附件 5 的模板把标签写成 `0:10-0:20` …
`0:00+1-0:10+1`，那是把 144 个时刻两两配对当区间，整列右移了一格：少了
`[0:00,0:10)` 这一段，末尾多出一个并不存在的 `[0:00+1,0:10+1)`。本文按时间顺序
写入 144 个数（位置顺序与模板一致），标签写成 `0:00-0:10` … `23:50-0:00+1`，
即把最后一格的名称写对。论文附录 B.1 说明了这一点。

**② 附录 D 里的表以日期为列。** 题面原表把四个日期并排、每个日期带子列，
按字面排出来是 8–9 列，在 A4 纵向里会挤到表头被截断、读不出来。附录 D 改为
**日期为列**（字段一项不少），并把表 2 的「充电量」「放电量」拆成两张表。
论文附录 D 的引言写明了这个取舍。

## 已知局限

- **问题 3 的调整收益主要来自偏差订正与及时纠偏**。预报精度并未随发布时刻
  接近而显著变好（论文 7.5 节），因此「有新预报就调整」并不自动划算；实测
  加入 6:00/12:00/18:00 三次调整合计少花约 45 万元。
- **负荷按可准确预测处理**。附件只给了光伏预报，题目未给负荷预报；若负荷也
  有误差，紧急购电会显著上升，本文未做该敏感性分析。
- **偏差与标准差只用了 1 月（前 31 天）标定**，2 月起应用以避免使用未来
  信息。若预报误差的分布随季节漂移，标定窗口需滑动。
- **储电量区间上下界在问题 1 中同时取到**（1200 与 10800），说明容量而非
  功率是瓶颈；这一结论依赖题目给定的 [1200, 10800]，换参数需重算。
- **紧急购电滤掉了 1e-3 kWh/步 以下的量**（约 6 W）。这是线代求解器的可行性
  容差留下的残差，不滤会让紧急购电表里混满 0.0006 kWh 的假时段；对全天费用
  的影响不足 5 元。论文附录 B.3 有说明。

## 交付流水线里顺带修掉的两个框架缺陷

`paper.docx` 由框架的 `normalize → pandoc → python-docx` 管线生成，过程中
发现并修复了 `backend/app/utils/common_utils.py` 的两个缺陷（已提交）：

1. **表题注被当成正文排版**。段落角色靠文本正则判定，只认
   `一、`/`1.1 `/`1.1.1 ` 三种标题，于是 `表 N: …` 题注、`参考文献`、
   `附录 A …`、`问题 1` 全部落到 else 分支被按正文重排（宋体小四 + 首行
   缩进两字），表名看起来像正文里的一句话。修法：新增表题注模式走图注
   格式（居中、小五），并在文本正则都未命中时退回 pandoc 给出的 Heading
   样式判断；首行缩进也跳过所有 Heading。
2. **表格单元格里的下划线被当成下标**。`_latex_cell_to_text` 的上下标
   替换原先无条件套在整格文字上，于是附录文件清单里的 `c_data.py` 被
   转成 `c𝒹ₐₜₐ.py`、`c_figs.py` 转成 `c𝒻ᵢ𝓰ₛ.py`。修法：转换只在
   `$...$` 区间内进行；同时删掉下标映射表里为凑满 26 个字母而填的错字形
   （原表 `b→ₑ` 会让 `$x_b$` 显示成 xₑ），无对应字形时保留 `_` 原样。

论文侧另有两处修正：markdown 竖线表不在框架的 `<table>` 计数内，2.1 节那张
「层次划分」表因此是全篇唯一没有题注的表；已改为 33 张表统一按正文顺序写死
题注，编号检查由 `fix_captions.py` 在编译前执行。附录 D 的 18 张表编号必须
顺着正文往下排（表 16…表 33），**不能写成「表 D-1」**——归一化补题注用的
正则是 `表\s*(\d+)[：:]`，认不出带字母的编号，会把它们当成没题注的表另补
一条，与自己写的撞成双份。

## 复现方式

```bash
cd _work
python c_solve.py         # 求解四个问题，生成 5 个 result*.xlsx
python c_tables.py        # 生成题目表 1/表 2/表 3 与附录 D 的 18 张表
python c_figs.py          # 生成插图
python verify.py          # 独立验证（只读结果文件反算 + 与附件 5 模板比对）
python fix_captions.py    # 编译前校验表题注编号与正文顺序一致
python splice_appendix_d.py  # 把附录 D 拼进 paper.md（幂等）
python apply_num_fixes.py # 把重算后的数值同步进论文（幂等）
python build_docx.py      # 由 paper.md 编译论文 Word
```

`build_docx.py` 需要 **backend 的 venv**（`backend/.venv/Scripts/python.exe`，
系统 Python 没有 bs4/pypandoc）；把 docx 导成 PDF 则要用**系统** Python
（venv 里没有 pywin32）。`fix_captions.py`、`splice_appendix_d.py`、
`apply_num_fixes.py` 均可重复运行，输出不变即可确认幂等。
