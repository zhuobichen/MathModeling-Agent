# 2026 CUMCM C 题：与公开解答的逐项对照

对照时间：2026-09-22。方法：找 GitHub 上公开的 C 题完整解仓库，**直接读它们的结果文件**
（`result*.xlsx` / `metrics.json` / `summary.json` / `*.csv`），而不是读它们的说明文档。
这一步很关键——下面第 1 节就会看到，有的仓库**文档里的数字与结果文件里的不一致**。

### 一个值得记下的现象：表 1 的逐项值不唯一

问题 1 的 LP 是**退化的**，最优解不唯一：五家的全天总量与费用一致，但表 1 那六个指定时段
的**逐项值分成了两类**：

| 时段 | 本文 / li2396803 / weizhixiao396 | Sen-illion（现行文件） | yuchi423 |
|---|---|---|---|
| 10:00-10:10 | 0 | 0 | 0 |
| 12:00-12:10 | 480.4124 | 486.4029 | 0 |
| 14:00-14:10 | 0 | 0 | 0 |
| 16:00-16:10 | 445.4317 | 394.9315 | 445.4317 |
| 18:00-18:10 | 531.8940 | 636.9826 | 531.8940 |
| 20:00-20:10 | 0 | 0 | 0 |

三家落在同一个顶点上（本文、li2396803、weizhixiao396，本文表 2 的 12 个充放电值也与
weizhixiao396 逐位相同）；另外两家的费用只差 0.0986 元（0.0003%），却落在别的顶点上。
Sen-illion 自己的文档也印证了这一点：它的 `planning/Q1_notes.md` 里写的是
480.41 / 445.43 / 531.89（与本文一致），而 `results/Q1/table1.csv` 写的是
486.40 / 394.93 / 636.98——**同一仓库的两份记录互相矛盾**，说明不同次运行落到了不同顶点。

**结论：问题 1 的表 1/表 2 只应校验总量与费用（以及等式约束），逐项值不可作为对错判据。**

## 2. 问题 2 / 4-2：0.08% 的差距，可完全归因于两处约定

| 方案 | 问题 2 / 元 | 问题 4-2 / 元 |
|---|---|---|
| 本文（SOC 自 1/1 滚动；不强制日闭环） | 12254765.72 | 12841054.36 |
| 本文改为对方的约定（2/1 起 SOC=6000 + 每日 0:00=24:00 闭环） | **12245046.92** | **12830486.39** |
| li2396803（就是上面这套约定） | **12245046.915277628** | **12830486.386656133** |

**改齐约定之后，本机复算与 li2396803 逐位相同**（12 245 046.92 与 12 830 486.39）。两处约定是：

1. 2 月 1 日的起始 SOC：对方直接置 6000 kWh（附件 1 附录给的初值），本文从 1 月 1 日起滚动
   优化，到 2 月 1 日已落到下界 1200 kWh；
2. 是否强制每天 0:00 与 24:00 储电量相同：题面只在**问题 1** 里写了这一条，本文按字面不用于
   问题 2/3，对方则全程沿用。

两处约定合计影响 0.079%（9718.80 元）。本文保留字面读法（题面确实没要求日闭环），
但这个差异是可复现、可解释的，不是求解错误。

## 4. 本次对照查出的一处实质错误（已修正）

对照中发现本文上一版有一个**方向性错误**，已改正并重跑：

**附件 3 的整点预报是「整点那一瞬间」的值，不是「那一小时的平均值」。** 本文原先把它
当小时均值、铺在 `[issue+k-1, issue+k)` 上，相当于整条预报曲线**早了一个小时**。
判据是拿预报与附件 2 实测比 MAE（21900 个样本）：

| 对时方式 | MAE / kW | r |
|---|---|---|
| 整点 X = issue+k | **117.2** | 0.9957 |
| 整点 X = issue+k-1 | 667.0 | 0.9401 |
| 小时均值 (h, h+1] | 308.8 | 0.9856 |

改成整点插值后，全年费用 14961318.24 → **13802767.33 元（−7.8%）**，紧急购电
405165 → 206928 kWh（−49%）。

**连带被推翻的结论**：上一版报告"附件 3 的预报带系统性偏差"（0:00 发布、步长 9 小时处
实际比预报低 666 kW），并据此做偏差订正与分位对冲。那个 666 kW 正是**拿整点预报去比
小时均值**算出来的假象——早晨爬坡段的"小时均值 − 整点值"本来就约等于坡高的一半。
改成同刻比对后，各发布时刻的偏差均值只剩 +26 / +10 / −3 / 0 kW，标准差 370 / 236 / 70 kW，
**预报误差接近零均值**。因此两步处理都不再划算（全年消融：不订正不对冲 1380.3 万 <
加订正 1383.3 万 < 加对冲 1383.5 万）。

论文第 7 章的叙述、表 8/表 9、图 3 与附录 D 已按此重写。

## 5. 其它被对照印证的判断

- **问题 2 的紧急购电恒为 0**：li2396803 的结果是 3.89×10⁻¹¹ kWh（数值零），
  weizhixiao396 的先知模型也是 0——与本文"先证明再计算"的结论一致。
- **微网接口侧报充放电量**：li2396803、weizhixiao396 与本文一致（另有一家用电池侧，
  两者相差恰好 0.9 倍，是同一条调度）。
- **弃光**：本文问题 2 弃光 990168 kWh，与问题 1 的 0 形成对比（问题 1 是单日闭环、
  问题 2 是全年电池长期贴底）。
- **是否有必要引入 6/12/18 的调整**：本文实测"不调整 13667671.88 元 < 调整 13802767.33 元"，
  即在题面的惩罚结构下调整净亏 1.0%。其它仓库多答"需要"，但它们没有给出"不调整"的对照成本，
  因此无法判断是结论不同还是没算这一步。
