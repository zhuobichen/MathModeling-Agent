## 1. 最强的一致性证据：公式逐字相同

公开帖 5.2 节给出的 MATLAB 航段能耗函数：

```matlab
function E = legEnergy(drone, q, d_horiz, h_up, h_down)
    Lq = drone.rangeEmpty - (drone.rangeEmpty - drone.rangeFull) * ...
         (q / drone.maxPayload) ^ (3/2);
    E_hor = drone.batteryEnergy * d_horiz / Lq;
    m_total = drone.emptyMass + q;
    E_up = m_total * 9.8 * h_up / (drone.etaClimb * 3.6e6);
    E = E_hor + E_up;
end
% 往返：E2 = legEnergy(drone, 0, d_horiz, h_descend, h_climb)
```

本文 `d_core.py`：

```python
Lq = L0 - (L0 - LF) * (q / Q) ** 1.5
E_hor = d / Lq * E_use
E_up  = (m_empty + q) * 9.81 * h_up / eta_up / 3.6e6
```

**逐项相同**（$g$ 取 9.8 与 9.81，差异可忽略）。往返那一程两边都把「爬升/下降高度对调」
——本文的 `T.seg(g, site, "O01", 0.0)` 中 $h^+=\max(0,H_{\text{cruise}}-H_{\text{op,site}})$、
$h^-=\max(0,H_{\text{cruise}}-H_{\text{op,O01}})$，与 `legEnergy(..., h_descend, h_climb)`
是同一件事。

**这条的意义**：题目把 `E^hor`、`E^up` 只给了名字与单位、没给表达式，两份独立实现
反推出来的形式完全一样，说明这个反推不是猜的。

## 2. 三处可用公式或数据判定真伪的出入

### 2.1 「总能耗 30–50 kWh」低于模型自己的物理下限

公开帖 6.2 节写「总能耗：约 30–50 kWh」，同节标注为**预期**。

用它自己的能耗公式可以卡出下限：水平能耗至少是「总航程 ÷ 空载航程 × 电池能量」。

**表 2: 问题二方案的总水平航程与能耗下限**

<table>
<tr><th>机型</th><th>总水平航程 / km</th><th>纯水平能耗下限 / kWh</th></tr>
<tr><td>A</td><td>215.4</td><td rowspan="4"><b>合计 95.7</b></td></tr>
<tr><td>B</td><td>141.5</td></tr>
<tr><td>C</td><td>119.3</td></tr>
<tr><td>合计</td><td><b>476.2</b></td></tr>

即：**完全不载货、且不计任何爬升，也至少要 95.7 kWh**。它给的 30–50 kWh 只有下限的
1/3~1/2，**在它自己的公式下不可能达到**。本文实算 107.41 kWh，距下限 12.2%。

### 2.2 「S015 上 A、B 机型载荷受限明显」——用它的代码复算也不成立

公开帖 6.1 节：「远距离或高海拔服务区（如 S015，海拔 444.5 m）：A、B 机型载荷
**受限明显**，C 机型因电池能量大（8 kWh）优势突出。」

按其代码口径（配实测 DEM）复算，**S015 上三个机型全部满载**（25/30/80）。原因是
S015 虽然海拔最高，但距 O01 只有约 6.0 km，水平航程短，A 机满载往返只用掉能耗预算
的 **72.8%**，还有 27% 余量。

真正卡住的是 **S008**：距 O01 约 8.1 km（最远），B、C 两型都要降载。它把
「高海拔」当成了限制来源，权重看反了——本题的能耗由**水平航程**主导（占单架次
能耗 90% 以上），海拔只影响爬升项。

### 2.3 「S015 可用 A 型单架次完成」——被装载体积否掉

公开帖 6.1 节：「S015 仅 3 箱（约 25 kg），可用 A 型单架次完成。」

S015 的三个货箱确实是 25.0 kg，但**体积是 0.0670 m³，超过 A 型的可用装载体积
0.06 m³**。所以 A 型必须 **2 架次**——这是全题唯一由**体积**（而不是质量或能量）
触发的架次增加。

| 机型 | 可用装载体积 | S015 需要架次 | 受限于 |
|---|---|---|---|
| A | 0.06 m³ | **2** | 体积 |
| B | 0.073 m³ | 1 | — |
| C | 0.25 m³ | 1 | — |

同一节里还有一处数字不对：「S001 需求最大（15 箱，约 **200 kg**）」——实测 S001 是
15 箱、**154.0 kg**。（机型选择的判断是对的：S001 确需 C 型多架次。）

### 2.4 按编号切的分区分案违反题目约束

题目原文：「若同一运输架次同时涉及多个服务区，则这些服务区应划入同一任务组。」

公开帖给的分区是按**编号顺序**切的：

- 2 分区：`{S001–S008}` / `{S009–S015}` → 实测**跨组架次 5 条**
- 3 分区：`{S001–S005}` / `{S006–S010}` / `{S011–S015}` → 实测**跨组架次 10 条**

两种切法都不满足题目要求（该帖也没有检查这一条）。

本文的做法：先用并查集求服务区的**共现连通分量**，实测 15 个服务区连成 **5 个分量**：

```
{S001,S006,S011}  {S002,S004,S008,S012}  {S003,S007,S015}
{S005,S009,S013}  {S010,S014}
```

分区的自由度只在这 5 个分量之间。在分量上聚类，K=2 与 K=3 的跨组架次都是 **0**。

**这一条是本题最容易踩的坑**：先做运输调度、再做分区时，分区不是自由的——它被
调度结果反向约束住了。本文第一版也是直接对服务区做地理聚类，被自己的校验脚本
查出 3 条与 5 条跨组架次后才改正的。

## 3. 对得上的地方

- **公式逐字相同**（见第 1 节），两份独立实现反推出同一个 `E^hor`、`E^up`。
- **问题三需要中继**：该帖判断「部分航段（如 O01→S015）直连不可用」。本文逐时刻
  诊断的实际结果是 **30.6% 的航程采样点无直连**，S015 的直连缺失率 30.2%，方向一致。
- **中继悬停点选高地**：该帖说「悬停位置选在运输航段中点附近的高地」；本文在 DEM
  上按约 1 km 格网取最高点作候选，最终两个站位海拔 817 m 与 838 m（离地 300 m）。
- **分区的定性结论**：2 分区组间不均衡、3 分区更均衡但资源冗余更大——本文实算的
  架次极差 25（K=2）对 9（K=3），资源缺口 3 架 B 型对（3 架 B 型 + 1 架中继），
  与该帖判断一致。
- **S001 需 C 型多架次**：本文实算 C 型 2 架次（其余机型分别要 10 架次与 7 架次），
  与该帖判断一致。

## 4. 相互检验的结论

| 维度 | 判定 |
|---|---|
| 物理模型（公式） | **完全一致**，可互相印证 |
| 数值结果 | **无法对齐**——该帖所有数值都标「预期」，其代码里 DEM 是占位符，实际没有跑过地形 |
| 可核对的定性结论 | 5 条一致、3 条不成立（2.2 / 2.3 / 2.4） |

**这次相互检验对本文的价值**，与其说是"对齐"，不如说是**确认了公式口径**，并且
反过来说明了一件事：**这题的对错分水岭不在公式，在"有没有真的读 DEM"和"有没有
检查题目给的约束"**。该帖的公式推导是完整且正确的，但三个可判定的错误全部出在
「把占位/估计当成结果」上。

## 5. 本次检验给本文带来的两处改进

1. **补上能耗的解析下界**。被提醒"能耗数字要先卡一个下限"，本文据此在论文 9.2 节
   给出 $E_{\min}=\sum_g D_gE_g^{\text{use}}/L_g^0$（本文 95.7 kWh）——它比任何单点
   结果都更能说明方案的质量，也让"30–50 kWh"这类不可能的数一眼可见。
2. **把「分区受调度反向约束」写成显式的建模步骤**，并在 `verify.py` 里固化成一条
   检查项。这是四问之间"数据继承关系"最具体的一处体现，也是本文第一版出错的地方。

## 6. 没能核实的东西

- 官方评测（评分细则、标准答案）无法获得，无法判断"哪种读法会被判对"。本文的策略
  是：**能用数据判定的口径就用数据判定**（如直连链路、共现分量、体积约束），
  **不能用数据判定的就把两种读法都算出来、写清差多少**。
- 该帖的遗传算法与 PSO 优化部分只有代码骨架与 `fprintf` 输出语句，没有可复现的
  运行结果，故无法核对其收敛值。本文的办法是直接用它的公式反推量级下限——能把
  "明显不可能"的数排掉，但不能替它把数算出来。
- 另有两篇 CSDN 解析帖返回 521，取不到原文。
